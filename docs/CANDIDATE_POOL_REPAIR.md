# A/C候选池数据链路修复

## 已定位问题

- 东方财富涨停池参数 `ut` 多出尾部字符，接口返回空值却被计作成功；新浪备用行情没有涨停价。
- 历史预算先按板块、成交额裁剪，涨停与名单外独立事件没有获得优先历史验证。
- 自动公告永远未核验、无影响分；只查趋势名单，独立催化发现存在循环依赖。
- 后续阶段固化池分类，新的已核验事件无法进入C池。旧页面把所有空池统一解释为无符合条件候选。

## 最终行为

1. 修正涨停池参数；校验实际 `qdate` 和完整条数。缺失、空值、过期、截断都作为无法确认处理。供应商涨停价须与同日行情收盘相符，炸板不因旧名单重新入池。
2. 优先为独立事件、涨停线索分配历史预算。供应商不可用时，对沪深已存在至少61根日线的普通证券采用保守价格规则，排除新股标记、风险警示、未知市场、价格异常和前收盘不连续。规则身份、日线推导板数与供应商板数分别展示，绝不把推导冒充官方梯队；北交所需要明确供应商证据。特殊复牌及完整历史除权仍未覆盖。
3. 巨潮独立扫描最近3日重大合同、签订合同、业绩预告关键词，每词最多2页，每阶段最多读取20份官方PDF。未知域名、非PDF、超过10MB/40页、发行人代码不符及歧义文档均不自动核验。
4. 正文规则仅接受明确量化事实：已签销售合同占完整年度营收至少10%；或明确已签署生效、总额至少10亿元的销售合同；或归母净利润盈利且预告同比增长下限至少50%。规则分70/80及依据公开，合同总额不等于当期收入或利润，业绩预告不等于已实现业绩。其他类型保留待人工核验，不因标题利好自动入池。
5. 晚间、隔夜、盘前允许已核验且仍新鲜的独立事件进入C池，价格使用已存档的完整收盘行情，再补历史验证。A/B继续沿用前序；午盘只验证盘前名单。风险、历史因子与分数门槛继续适用。
6. 每池附带覆盖、发现、核验及入选数量与缺口说明；旧快照显示缺少证据记录，不改写过去候选或历史效果。

## 验证

`pytest -q` 覆盖空/旧/截断涨停响应、炸板、新股、异常价格、历史间隔、官方PDF事实识别、假利好、采购合同与收入合同区别、名单外独立事件及完整阶段链。

`python -m src.collectors.verify_candidate_evidence` 在当前时点只读检测数据源，结果写入 `artifacts/candidate-evidence-verification/result.json`。不修改正式阶段、不补写早盘、不写Google Docs。

新规则自部署后的新任务生效。已有完成快照继续冻结；A池完整重新发现从下一次合法16:00收盘扫描开始。是否有候选取决于当时证据与筛选，修复不保证每天非空。
